# Минусатор — инструкции для Claude Code

## Что это за проект
Веб-инструмент для специалиста по контекстной рекламе (Яндекс Директ).
Пользователь загружает отчёт по поисковым запросам (CSV / XLSX), инструмент
находит мусорные запросы и собирает из них готовый список минус-слов,
который можно сразу скопировать в Директ.

Полное ТЗ: `docs/SPEC.md`. План работ по этапам: `docs/ROADMAP.md`.
Перед началом любой задачи прочитай оба файла.

## Жёсткие ограничения (не нарушать)
1. **Всё бесплатно.** Никаких платных API, ключей, подписок, серверов.
2. **Только фронтенд.** Сайт статический, хостится на GitHub Pages.
   Никакого бэкенда, БД, серверных функций.
3. **Данные не покидают браузер.** Файлы обрабатываются локально в JS.
   Никаких запросов на внешние сервисы с данными пользователя. Это важное
   преимущество продукта: отчёты клиентов — конфиденциальная информация.
4. **Без ИИ-API.** Логика классификации — правила и словари (`src/dictionaries`).
5. Зависимости — только бесплатные open-source npm-пакеты.

## Стек
- Vite + React + TypeScript
- Tailwind CSS
- PapaParse — парсинг CSV/TSV
- SheetJS (`xlsx`) — парсинг XLSX
- Стемминг русских слов — свой модуль (Snowball/Porter для русского) в `src/lib/stemmer.ts`
- Хранение настроек пользователя — `localStorage` (обернуть в try/catch)
- Деплой — GitHub Actions → GitHub Pages (`.github/workflows/deploy.yml` уже готов)

## Важно для деплоя
- В `vite.config.ts` выставить `base: './'`, чтобы сайт работал на
  `https://<user>.github.io/<repo>/` при любом имени репозитория.
- Сборка в папку `dist`.

## Структура (целевая)
```
src/
  components/      UI-компоненты
  lib/
    parser.ts      чтение CSV/XLSX, поиск строки заголовков, маппинг колонок
    stemmer.ts     русский стеммер
    classifier.ts  правила классификации запросов
    minus.ts       сборка списка минус-слов, дедупликация, форматирование
  dictionaries/    JSON-словари стоп-слов по категориям
  App.tsx
samples/           тестовые отчёты для проверки
```

## Стиль работы
- Интерфейс полностью на русском языке.
- Пользователь — не программист. Объясняй, что сделал, простыми словами.
- Логику (`src/lib`) покрывай тестами на Vitest.
- После каждого этапа из ROADMAP: `npm run build` должен проходить без ошибок,
  проверь работу на файлах из `samples/`.
- Не добавляй функции, которых нет в SPEC, без согласования.
