# ТЗ: Минусатор

## Проблема
Специалист по контексту регулярно выгружает отчёт по поисковым запросам из
Яндекс Директа и вручную, глазами, ищет нецелевые запросы, чтобы добавить
минус-слова. Это занимает часы и часть мусора пропускается, а это слитый бюджет.

## Решение
Веб-страница: загрузил отчёт → увидел подсвеченные мусорные запросы с
причиной → поправил галочками → скопировал готовый список минус-слов.

## Пользовательский сценарий
1. Открывает сайт, перетаскивает файл отчёта (или выбирает через кнопку).
2. Инструмент сам находит нужные колонки. Если не нашёл — даёт выбрать вручную.
3. (Опционально) Указывает «белый список» — слова своего бизнеса, которые
   нельзя минусовать (бренд, ключевые товары, свой город).
4. (Опционально) Указывает конкурентов и свой город, чтобы ловить чужие бренды и чужое гео.
5. Видит таблицу запросов:
   - статус: 🔴 мусор / 🟡 подозрительно / 🟢 ок
   - причина (категория правила или метрика)
   - показы, клики, расход, конверсии
   - фильтры по статусу и категории, сортировка, поиск
6. Видит панель «Кандидаты в минус-слова»: список слов с частотой,
   суммарным расходом и галочками. Может снять/поставить галочку,
   добавить слово вручную.
7. Нажимает «Скопировать» — получает список в формате Директа.
   Также можно скачать .txt.

## Входные данные
Отчёт по поисковым запросам Директа (Мастер отчётов или «Поисковые запросы»).
Форматы: CSV, TSV, XLSX.

Особенности, которые надо учесть:
- В выгрузках Директа сверху бывают служебные строки (название отчёта,
  период). Парсер должен сам найти строку заголовков (первая строка,
  где есть колонка с «запрос»).
- Разделитель может быть `;`, `,` или табуляция — определять автоматически.
- Кодировка: UTF-8 или Windows-1251 — определять автоматически.
- Числа могут быть с запятой как десятичным разделителем и с пробелами («1 234,56»).
- Прочерк «-» или пусто в метриках = 0.

Маппинг колонок (по вхождению подстроки, без учёта регистра):
| Поле        | Возможные названия |
|-------------|--------------------|
| query       | «Поисковый запрос», «Запрос» |
| campaign    | «Кампания», «Название кампании» |
| group       | «Группа», «Название группы» |
| impressions | «Показы» |
| clicks      | «Клики» |
| cost        | «Расход», «Стоимость» |
| conversions | «Конверсии» |

Обязательна только колонка query. Остальные — если есть.

Пример: `samples/search_queries_sample.csv`.

## Логика классификации
### 1. Правила по словарям (`src/dictionaries/*.json`)
Категории:
- `free` — бесплатно, даром, скачать, торрент…
- `jobs` — вакансии, работа, зарплата, резюме…
- `diy` — своими руками, самому, как сделать…
- `info` — что такое, отзывы, форум, википедия, реферат…
- `education` — курсы, обучение, для студентов, реферат…
- `used` — б/у, авито, бу, с рук…
- `adult` — 18+ контент (минимальный словарь)

Каждый словарь — массив слов/фраз. Сравнение по основам слов (стеммер),
чтобы «бесплатно», «бесплатный», «бесплатные» ловились одним правилом.
Пользователь может включать/выключать категории (галочки в настройках) —
например, для магазина б/у техники категория `used` не мусор.

### 2. Пользовательские правила
- Конкуренты — список брендов → категория `competitor`.
- Свой город → запросы с другими городами из `cities.json` получают `geo`.
- Белый список — слова, которые никогда не становятся минус-словами,
  и запросы с ними не помечаются 🔴 (максимум 🟡).

### 3. Правила по метрикам (если есть колонки)
- Клики ≥ N и конверсий = 0 → 🟡 «кликают, но не конвертируются»
- Расход ≥ X и конверсий = 0 → 🟡 «тратит бюджет без результата»
- N и X настраиваются, по умолчанию N = 5, X = 500.

### Итоговый статус
- 🔴 — сработало словарное/пользовательское правило
- 🟡 — сработало только метрическое правило, или 🔴 перебит белым списком
- 🟢 — ничего не сработало

## Сборка минус-слов
- Из 🔴 запросов берётся слово, на котором сработало правило
  (например, «бесплатно»), а не весь запрос.
- Дополнительно: кнопка «Показать слова, которые есть только в 🔴/🟡
  запросах» — частотный анализ слов, которые не встречаются в 🟢 запросах.
  Это помогает находить мусор, которого нет в словарях.
- Стоп-слова русского языка (предлоги, союзы: в, на, для, и, с…)
  не предлагаются как минус-слова.
- Дедупликация по основе слова.
- Сортировка кандидатов по суммарному расходу, затем по частоте.

### Формат вывода (настраивается переключателем)
- По одному слову в строке: `бесплатно`
- С минусом в начале, через пробел: `-бесплатно -скачать -вакансии`
- Фиксация формы (`!слово`) — опционально, галочкой.

Показывать счётчик символов итогового списка. Предупреждать, если
список очень длинный (у Директа есть лимит на длину минус-фраз кампании —
актуальное значение указать в константе, легко поменять).

## Интерфейс
- Одна страница, светлая тема, аккуратный современный вид.
- Блоки: загрузка файла → настройки (сворачиваемые) → сводка (сколько
  запросов, сколько мусора, сколько денег ушло на мусор) → таблица → минус-слова.
- **Сводка «Сколько бюджета ушло на мусор»** — главная цифра на экране,
  крупно. Это то, что специалист покажет клиенту/руководителю.
- Настройки (белый список, конкуренты, город, категории, пороги)
  сохраняются в localStorage и подставляются при следующем визите.
- Работает на десктопе; на мобильном — без поломок вёрстки.
- Внизу: «Файлы обрабатываются в вашем браузере и никуда не отправляются».
